채팅이나 story object, novel을 자신이 원하는 언어로 번역이 가능한 기능을 만들어볼거야. 다만 다국어 지원에 가까워.
유저의 UX flow는 다음과 같아.

  설정에서 primary language를 선택한다. (기본값은 영어)
  그리고 optional로 secondary language를 선택할 수 있다. (기본값은 null)
  secondary language가 설정이 되어있으면, 채팅의 수정버튼 왼쪽에 번역 버튼이 생기고, story object나 novel의 ai edit 버튼 왼쪽에도 번역 버튼이 생긴다.
  번역버튼을 누르면 secondary language로 번역이 되고, 다시 누르면 primary language로 돌아온다.
  이때 story object나 novel의 경우에는, 버튼 오른쪽에 조그만한 버튼을 누르면 다른 언어로도 번역할 수 있는 팝업이 뜬다.

전체적인 구조는 다음과 같아.
일단 데이터 저장구조를 완전히 뜯어 고칠거야. StoryObject를 기준으로 이야기를 해볼게. 일단 스토리 오브젝트는
{
  name: string;
  description: string;
  /*메타데이터*/
}
이런 식으로 저장이 되어있잖아.
이걸 다국어 지원이 가능하게 바꿔볼거야.
{
  data: {
    English: {
      name: string;
      description: string;
    };
    Korean: {
      name: string;
      description: string;
    };
    /*추가 언어*/
  };
  /*메타데이터*/
}

데이터 구조를 이런식으로 바꿀거야. 그리고 지금 설정에서 언어를 String으로 받고있거든. 그러니깐 data안에 어떤 언어가 들어갈지는 자유롭게 정해져야돼. 만약 primary 언어가 현재 오브젝트에 존재하지 않으면 대충 존재하지 않는다는 알림을 띄우고 옆에 번역하기 버튼을 띄울거야.
버전에 대한 지원도 해야되니깐 각 버전별로 그 버전의 data를 저장하는 구조로 가자. 이렇게 하는 이유는.
만약 어떤 유저가 영어를 primary로 하고 한국어를 secondary로 한다고 했을때.

영어로 AI에게 생성시키도록함 -> 한국어로 번역함 -> 한국어버전을 수정함 -> 다시 영어로 바꾸면 원래 있는 영어데이터가 아니라 새로운 버전에 영어의 데이타가 없는걸로 취급해서 한국어 버전을 기준으로 영어 번역을 실행함.

그리고 만약 유저가 primary언어를 바꾸었는데 이미 생성된 데이터에 그 언어로된 데이터가 없으면 현재 이 오브젝트에 현재 이 언어의 데이터가 없으니 데이터를 생성하겠냐는 알림을 띄운다음 원래 있던 데이터중 하나를 골라 현재 primary로 번역해주는 느낌으로 갈거야.

그리고 당연하지만 번역버튼을 눌렀을때 현재 버전의 데이터가 있으면 번역을 따로 보내지 말고 데이터에서 불러올거야.

그리고 translation service에서 이와 같은 서비스를 전체적으로 관리를 할거야. ai edit서비스가 하는 일과 비슷하게 거기서 데이터를 받아와서 llm에게 번역을 시키고, 그 결과를 파싱해서 저장하는 역할을 할거야.

지금 구현을 거의 다 했는데 story object에서 ai가 영어로 생성한다음 한국어로 번역하고 그 한국버전을 유저가 수정해서 새로운 버전을 만들면 그게 수정하기 전 언어인 한국어가 아니라 영어로 저장되고 있어. 그걸 그대로 영어로 저장한 다음에 유저에게 기본언어로 이걸 번역할 것이냐 물어보는 창을 띄우고 기본언어로 번역해서 채워넣는 기능까지 추가해줘.
